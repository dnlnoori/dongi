# دنگی (Dangi) — تقسیم و تسویه گروهی

نسخه MVP وب‌اپلیکیشن فارسی و راست‌چین برای ساخت صورتحساب گروهی، تقسیم مبلغ بین افراد، ساخت لینک پرداخت اختصاصی و پیگیری تسویه‌ها.

## امکانات پیاده‌سازی‌شده

- پنل فروشنده با ورود و ثبت‌نام ایمیلی
- ساخت صورتحساب با مبلغ کل، شماره موبایل مشتری، توضیحات و شماره کارت
- صفحه عمومی صورتحساب برای مشتری
- تقسیم مساوی، درصدی و مبلغ دلخواه (با کنترل مجموع سهم‌ها)
- ساخت لینک پرداخت اختصاصی برای هر فرد
- نمایش وضعیت پرداخت و مانده حساب
- داشبورد فروشنده با جست‌وجو و فیلتر وضعیت
- جزئیات هر صورتحساب با تاریخ ایجاد سهم و زمان پرداخت
- تنظیمات کسب‌وکار، شماره کارت پیش‌فرض و توضیحات پیش‌فرض
- گزارش پیامک‌های آزمایشی
- آداپتورهای مجزا برای درگاه پرداخت و پیامک
- رابط واکنش‌گرا برای موبایل و دسکتاپ

## فناوری‌ها

- Next.js App Router + TypeScript + React
- Tailwind CSS
- Supabase Auth + PostgreSQL + Row Level Security
- Vercel برای استقرار

## راه‌اندازی محلی

پیش‌نیاز: Node.js 20.9 یا جدیدتر (پیشنهاد: Node 22) و یک پروژه Supabase.

1. در Supabase یک پروژه بساز.
2. فایل `supabase/migrations/0001_init.sql` را در بخش **SQL Editor** پروژه اجرا کن.
3. فایل `.env.example` را به `.env.local` کپی کن.
4. مقدارهای زیر را از بخش Project Settings → API در Supabase بردار و وارد کن:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `SUPABASE_SERVICE_ROLE_KEY`
5. مقدار `NEXT_PUBLIC_APP_URL` را در توسعه `http://localhost:3000` قرار بده.
6. نصب و اجرا:

```bash
npm install
npm run dev
```

سپس `http://localhost:3000` را باز کن و حساب فروشنده بساز.

> اگر تأیید ایمیل Supabase فعال باشد، پس از ثبت‌نام باید ایمیل را تأیید کنی. برای تست محلی می‌توانی Email Confirmations را در تنظیمات Auth خاموش کنی.

## متغیرهای محیطی

| متغیر | توضیح |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | آدرس پروژه Supabase |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | کلید عمومی Supabase؛ قابل استفاده در مرورگر |
| `SUPABASE_SERVICE_ROLE_KEY` | کلید محرمانه سرور؛ هرگز در کد کلاینت یا Git قرار نگیرد |
| `NEXT_PUBLIC_APP_URL` | دامنه نهایی برنامه برای ساخت لینک‌های پیامک |
| `PAYMENT_PROVIDER` | فعلاً فقط `test` |
| `SMS_PROVIDER` | فعلاً فقط `mock` |

## تست جریان محصول

1. با ایمیل فروشنده ثبت‌نام کن.
2. از پنل، یک صورتحساب جدید بساز و شماره موبایل خودت را وارد کن.
3. در جزئیات صورتحساب، لینک مشتری را باز کن.
4. روش تقسیم را انتخاب کن و نام، موبایل و سهم افراد را وارد کن.
5. بعد از ثبت، لینک پرداخت هر نفر در صفحه عمومی صورتحساب ظاهر می‌شود.
6. لینک پرداخت هر نفر را باز کن و دکمه «پرداخت آزمایشی سهم من» را بزن.
7. به صفحه صورتحساب و پنل فروشنده برگرد؛ تیک سبز، مانده حساب و زمان پرداخت به‌روزرسانی شده‌اند.

## انتشار روی GitHub و Vercel

### GitHub

یک repository خالی در GitHub بساز، سپس از داخل پوشه پروژه اجرا کن:

```bash
git init
git add .
git commit -m "Initial Dangi MVP"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/dangi-app.git
git push -u origin main
```

فایل `.env.local` به‌دلیل `.gitignore` وارد Git نمی‌شود.

### Vercel

1. در Vercel گزینه **Add New → Project** را بزن و repository را Import کن.
2. Framework به‌صورت خودکار Next.js تشخیص داده می‌شود.
3. در Project Settings → Environment Variables، همه متغیرهای بالا را وارد کن.
4. برای `NEXT_PUBLIC_APP_URL` دامنه نهایی Vercel را قرار بده.
5. `PAYMENT_PROVIDER=test` و `SMS_PROVIDER=mock` را نگه دار.
6. Deploy را اجرا کن.

## مرزهای نسخه آزمایشی و نکات امنیتی

- **پرداخت واقعی انجام نمی‌شود.** آداپتور `TestPaymentProvider` با RPC دیتابیس وضعیت سهم را آزمایشی «پرداخت‌شده» می‌کند. قبل از دریافت پول واقعی باید آداپتور درگاه، ساخت تراکنش، اعتبارسنجی سمت سرور، callback و webhook امضاشده درگاه پیاده‌سازی و تست شوند.
- **پیامک واقعی ارسال نمی‌شود.** `MockSmsProvider` فقط پیام و شماره مقصد را در جدول `sms_logs` ثبت می‌کند. برای سرویس واقعی باید آداپتور ارائه‌دهنده پیامک، مدیریت خطا، محدودیت نرخ و قالب پیام اضافه شود.
- کلید `SUPABASE_SERVICE_ROLE_KEY` فقط در محیط سرور استفاده می‌شود و نباید با پیشوند `NEXT_PUBLIC_` تعریف شود.
- توابع عمومی تقسیم و پرداخت با توکن‌های تصادفی و بلند کار می‌کنند. قبل از استفاده تجاری باید محدودیت نرخ، پایش سوءاستفاده، سیاست نگهداری داده و تست امنیتی اضافه شود.
- شماره کارت صرفاً اطلاعات نمایشی سفارش است و پرداخت کارت‌به‌کارت را تأیید نمی‌کند.
- واحد پول در این نسخه تومان است.

## ساختار پوشه‌ها

```text
app/
  api/                 # API عمومی صورتحساب، تقسیم، پیامک و پرداخت تستی
  dashboard/           # پنل فروشنده
  i/[token]/            # صفحه عمومی تقسیم صورتحساب
  pay/[token]/          # صفحه پرداخت اختصاصی فرد
  login/ register/      # ورود و ثبت‌نام
components/              # اجزای رابط کاربری
lib/providers/           # آداپتورهای پیامک و پرداخت
lib/supabase/            # کلاینت‌های Supabase
supabase/migrations/     # ساختار دیتابیس و RPCها
```

- افزودن rate limit و CAPTCHA به endpointهای عمومی
